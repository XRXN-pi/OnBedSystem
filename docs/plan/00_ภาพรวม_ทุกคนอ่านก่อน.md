## 1. ระบบทำงานยังไง

```
 [Sensor Node WC-1]  KY-032 ───────────┐
                                       ├── ESP-NOW (ทุก 10 วินาที) ──> [Gateway ESP32]
 [Sensor Node WC-2]  MQ-137 + KY-032 ──┘                               KY-015, ultrasonic, water level
                                                                       คุมพัดลมเองทันที (ไม่รอเน็ต)
                                                                                │ MQTT
                                                                                ▼
                                   [NETPIE2020]  shadow + feed (เก็บข้อมูลดิบ) ──> [Dashboard]
                                         │ @msg/onbed/raw            ▲ @msg/onbed/cmd
                                         ▼                           │
                              [AI service (Python บนคอม)] ── ทำนายกลิ่นอีก 30 นาที → สั่งระดับพัดลม
                                         │
                                         └──> Discord แจ้งแม่บ้าน (gateway ก็แจ้งเองตอนพื้นเปียก)
```

1. **Sensor node** (2 ตัว firmware เดียวกัน) WC-1 (ทางเข้า) นับคนที่เดินผ่าน, WC-2 (โซนโถ) นับคนและอ่านค่ากลิ่น (มี MQ-137 ตัวเดียวที่ WC-2) แล้วส่งให้ gateway ทุก 10 วินาที
2. **Gateway** รับข้อมูลจาก node, อ่าน KY-015 (อุณหภูมิ/ความชื้น) / ultrasonic (มีคนอยู่ไหม) / water level (พื้นเปียก) ของตัวเอง, คุมพัดลม 3 ระดับ และส่งข้อมูลทั้งหมดขึ้น NETPIE ทุก 10 วินาที
3. **NETPIE** เก็บข้อมูลดิบ (feed) และให้ dashboard แสดงผล
4. **AI service** รับข้อมูล ใช้ Chronos-2 (โมเดลพยากรณ์สำเร็จรูป รันบนคอม) ทำนายค่ากลิ่นในอีก 30 นาที แล้วส่งคำสั่งระดับพัดลมกลับไปที่ gateway (ถ้า AI หลุด gateway คุมพัดลมเองจากค่ากลิ่นปัจจุบัน)
5. **Discord** แจ้งแม่บ้านเมื่อควรทำความสะอาด, พื้นเปียก หรืออุปกรณ์ขาดการเชื่อมต่อ

## 2. ข้อตกลงที่ทุกส่วนต้องใช้ตรงกัน (ห้ามเปลี่ยนเอง)

### 2.1 Wi-Fi
- บอร์ดทุกตัวใช้ hotspot มือถือชื่อ **`OnBed-Hotspot`** (ชื่อนี้ตั้งไว้ในโค้ดแล้ว) รหัสผ่านให้กลุ่มตั้งร่วมกันหนึ่งรหัส **ห้ามเขียนรหัสลงในไฟล์ที่ขึ้น GitHub** (ใส่เฉพาะใน `secrets.h` ของ gateway ซึ่ง `.gitignore` กันไว้แล้ว; node ใช้แค่ชื่อ hotspot ไม่ใช้รหัส)
- **ทุกคนตั้ง hotspot มือถือตัวเองให้ชื่อและรหัสตรงกันนี้** เวลาทดสอบคนเดียวที่บ้านจะได้ใช้โค้ดเดียวกันโดยไม่ต้องแก้ ส่วนวันรวมระบบ วันติดตั้งจริง และวัน demo ให้เปิด hotspot แค่เครื่องเดียว (ถ้าเปิดชื่อเดียวกันหลายเครื่อง บอร์ดจะต่อเครื่องไหนก็ได้ และ node กับ gateway อาจอยู่คนละ channel)
  - **iPhone:** ชื่อ hotspot คือชื่อเครื่อง เปลี่ยนที่ Settings → General → About → Name เป็น `OnBed-Hotspot` แล้วเปิด Personal Hotspot → เปิด **Maximize Compatibility** (บังคับเป็น 2.4 GHz) → ตั้งรหัสตามที่กลุ่มตกลง
  - **Android:** Settings → Hotspot & tethering → Wi-Fi hotspot → ตั้งชื่อ `OnBed-Hotspot`, รหัสตามที่กลุ่มตกลง, Band เลือก **2.4 GHz**
- ESP32 ใช้ได้แค่ 2.4 GHz ถ้า hotspot เป็น 5 GHz บอร์ดจะหาไม่เจอ
- Wi-Fi มหาวิทยาลัยใช้กับ ESP32 ไม่ได้ (สเปกเตือนไว้ และต้อง login ผ่านหน้าเว็บ)
- ถ้าจะเปลี่ยนชื่อหรือรหัส ต้องแก้ 3 ที่ให้ตรงกัน: `WIFI_SSID` ใน `firmware/sensor-node/include/config.h`, `WIFI_SSID` และ `WIFI_PASSWORD` ใน `firmware/gateway/include/secrets.h` ของคนทำ gateway

### 2.2 ข้อความ node → gateway (ESP-NOW)
```json
{"node_id": "WC-2", "seq": 1024, "odor": 1.42, "people": 5}
{"node_id": "WC-1", "seq": 1030, "people": 3}
```
| field | ความหมาย |
| --- | --- |
| `node_id` | `"WC-1"` = โซนทางเข้า, `"WC-2"` = โซนโถ |
| `seq` | เลขลำดับ เพิ่มทีละ 1 ทุกข้อความ (ใช้คำนวณ packet delivery rate) |
| `odor` | ค่ากลิ่น = R0/Rs ของ MQ-137 อากาศสะอาด ≈ 1.0 ยิ่งเหม็นยิ่งสูง, `-1` = เซ็นเซอร์หลุด **มีเฉพาะ WC-2** (WC-1 ไม่มี MQ-137 จึงไม่ส่ง field นี้) |
| `people` | จำนวนครั้งที่มีคนเดินผ่านใน 10 วินาทีที่ผ่านมา |

### 2.3 ข้อมูล gateway → NETPIE (ทุก 10 วินาที)
```json
{"data": {
  "ts": 1763280000, "ts_ms": 123,
  "wc1_people": 5, "wc1_seq": 1024, "wc1_recv": 1010, "wc1_online": 1,
  "wc2_odor": 1.10, "wc2_people": 2, "wc2_seq": 998,  "wc2_recv": 990,  "wc2_online": 1,
  "temp": 29.5, "hum": 78.0, "occupied": 1, "dist_cm": 45, "leak": 0,
  "fan_level": 1, "clean_status": "ok", "ai_online": 1, "estop": 0
 },
 "timestamp": 1763280000123}
```
- ชื่อ field ของ node สร้างอัตโนมัติจาก `node_id` (`WC-1` → `wc1`) เพิ่ม node ตัวที่ 3 ก็จะได้ `wc3_...` เองโดยไม่ต้องแก้โค้ด gateway
- `occupied`: 1 = ultrasonic เจอคนในระยะ (มีคนอยู่ในห้อง), `dist_cm` = ระยะที่ ultrasonic วัดได้ (ซม., 0 = อ่านไม่ได้)
- `clean_status`: `ok` = ยังไม่ต้อง, `soon` = ภายใน 30 นาที, `now` = ทันที
- `timestamp` (มิลลิวินาที) บอก NETPIE ว่าข้อมูลเป็นของเวลาไหน ข้อมูลย้อนหลังที่ค้างตอนเน็ตหลุดจึงถูกเก็บลง feed ตามเวลาจริง

### 2.4 MQTT topic
| Topic | จาก → ถึง | ข้อมูล |
| --- | --- | --- |
| `@shadow/data/update` | gateway → NETPIE | ข้อ 2.3 (dashboard และ feed อ่านจากตรงนี้) |
| `@msg/onbed/raw` | gateway → AI service | ข้อ 2.3 เหมือนกัน |
| `@msg/onbed/cmd` | AI service → gateway | `{"fan": 2, "status": "soon", "pred": 2.41}` |

### 2.5 NETPIE
- สุรสิทธิ์เป็นคนสร้างบัญชี project และ device ตามไฟล์ 03 ขั้นที่ 2 (จ. 16) แล้วส่งค่า Client ID / Token / Secret ให้คนที่ต้องใช้ทางแชทส่วนตัว
- Broker `mqtt.netpie.io` port **1883** (ปกติ) / **1884** (TLS) — ตาม [docs.netpie.io](https://docs.netpie.io/en/mqtt-api.html)
- Device 2 ตัว **อยู่ Group เดียวกัน** (ถ้าคนละ group ส่ง `@msg` หากันไม่ได้):
  - `gateway` ใช้กับ ESP32 gateway (และ `fake_gateway.py` ตอนทดสอบ)
  - `ai-service` ใช้กับ Python (`collect.py` / `service.py`)
- **Client ID เดียวกันต่อพร้อมกันได้ทีละโปรแกรมเท่านั้น** ถ้าเปิดซ้อนกัน ตัวเก่าจะหลุด เช่น ห้ามเปิด gateway จริงพร้อม `fake_gateway.py --live` และห้ามเปิด `collect.py` พร้อม `service.py`

## 3. ติดตั้งเครื่องมือ (ทุกคนทำวันแรก ~45 นาที)

### 3.1 คนที่แฟลช ESP32 (สิรวิชญ์, สุรสิทธิ์, ไอริณ)
1. ติดตั้ง **VS Code** จาก code.visualstudio.com
2. เปิด VS Code → แถบซ้ายกดไอคอน Extensions (สี่เหลี่ยม 4 ช่อง) → ค้น **PlatformIO IDE** → Install → รอจนเสร็จแล้วรีสตาร์ท VS Code (ครั้งแรกนานประมาณ 5–10 นาที)
3. เสียบบอร์ด ESP32 ด้วยสาย USB **ที่ส่งข้อมูลได้** (สายชาร์จอย่างเดียวจะไม่เห็นบอร์ด)
4. ถ้าคอมไม่เห็นบอร์ด ดูชิปเล็กๆ ใกล้ช่อง USB:
   - เขียนว่า **CP2102** → ลง driver "CP210x USB to UART Bridge" ของ Silicon Labs
   - เขียนว่า **CH340** → ลง driver "CH340" ของ WCH
5. วิธีเปิดโปรเจค: PlatformIO (ไอคอนหัวมด) → **Open Project** → เลือกโฟลเดอร์ที่มีไฟล์ `platformio.ini`
6. ปุ่มที่ใช้บ่อย (แถบล่างของ VS Code):
   - ✓ = Build (compile)
   - → = Upload (แฟลชลงบอร์ด)
   - 🔌 = Serial Monitor (ดูข้อความจากบอร์ด)
   - ชื่อ env เช่น `env:wc1` = กดเพื่อเลือกว่าจะ build แบบไหน
7. **ครั้งแรกที่กด Build จะโหลด library และ platform นาน 5–15 นาที** ต้องต่อเน็ต รอบหลังจะเร็ว
8. ถ้าอัปโหลดไม่ขึ้น ขึ้น `Connecting........_____` ให้**กดปุ่ม BOOT บนบอร์ดค้างไว้**จนเริ่มอัปโหลด

### 3.2 คนที่ใช้ Python (ณัฐณิชา, วัตตะนะ)
1. ติดตั้ง Python 3.11 หรือ 3.12 (64-bit) จาก python.org (Windows: ติ๊ก **Add python.exe to PATH**)
2. ในโฟลเดอร์ `ai/` ของ repo:
   ```bash
   python -m venv venv
   # Windows:      venv\Scripts\activate
   # Mac/Linux:    source venv/bin/activate
   pip install -r requirements.txt          # ณัฐณิชา (มี Chronos-2 + PyTorch ไฟล์ใหญ่ ใช้เวลา 10–20 นาที)
   pip install -r requirements-light.txt    # วัตตะนะ (ไม่ต้องลงโมเดล AI)
   ```
   เลือกรันบรรทัดเดียวตามชื่อตัวเอง
3. ทุกครั้งที่เปิด terminal ใหม่ต้อง activate venv ก่อน (ต้นบรรทัดจะขึ้น `(venv)`)

### 3.3 Git และ GitHub (ทุกคน)
1. สมัคร github.com และติดตั้ง Git จาก git-scm.com
2. ตั้งชื่อให้ตรงกับบัญชี GitHub **ไม่งั้น commit ไม่ขึ้นเป็นชื่อเรา และไม่นับเป็นงานของเรา**:
   ```bash
   git config --global user.name  "ชื่อผู้ใช้ GitHub"
   git config --global user.email "อีเมลที่สมัคร GitHub"
   ```
3. รับคำเชิญเข้า repo ทางอีเมล แล้ว clone:
   ```bash
   git clone https://github.com/<ชื่อเจ้าของ>/onbedsystem.git
   cd onbedsystem
   ```
4. ทุกครั้งก่อนเริ่มงาน: `git pull`
5. ทุกครั้งที่ทำส่วนหนึ่งเสร็จ:
   ```bash
   git add <ไฟล์หรือโฟลเดอร์ที่แก้>
   git commit -m "node: add ISR people counter"
   git push
   ```
   ถ้า push ไม่ผ่านเพราะมีคนอื่น push ก่อน ให้ `git pull` แล้ว `git push` อีกครั้ง
6. **ห้ามใช้ `git add .` ตอนมีไฟล์ secrets อยู่** ให้ add เฉพาะโฟลเดอร์ของตัวเอง และเช็ก `git status` ก่อน commit ทุกครั้งว่าไม่มี `secrets.h` / `config_secrets.py` / `gateway_secrets.py`
7. commit บ่อยๆ ทีละเรื่องเล็ก ไม่ต้องรอเสร็จทั้งหมด

## 5. Checkpoint ศุกร์ 20 พ.ย. (ส่งภายใน 23:59)

**ต้องเห็นในวิดีโอ (ไม่เกิน 2 นาที):** sensor node อ่านค่าจริง → ส่งถึง gateway ผ่าน ESP-NOW → gateway ส่งขึ้น NETPIE → dashboard แสดงค่าที่เปลี่ยนตามจริง

| คน | ต้องพร้อมก่อนมาวันศุกร์ (ทดสอบคนเดียวผ่านแล้ว) |
| --- | --- |
| สิรวิชญ์ | node ส่ง JSON ผ่าน ESP-NOW ได้ (ทดสอบกับบอร์ดรับทดสอบแล้ว) อย่างน้อย 1 ตัว ดีที่สุด 2 ตัว |
| สุรสิทธิ์ | gateway ต่อ NETPIE ได้ ส่งข้อมูลทุก 10 วินาที (ทดสอบด้วย `gateway_fake` แล้ว) อ่าน KY-015 ได้ |
| วัตตะนะ | dashboard แสดงค่าทุก field (ทดสอบด้วยข้อมูลจำลองแล้ว) เปิด feed แล้ว |

**ถ้าเซ็นเซอร์บางตัวยังไม่มา:** ใช้ potentiometer แทน MQ-137 (ต่อขาเดียวกัน หมุนแล้วค่าเปลี่ยน) และใช้ปุ่มกดแทน KY-032 (ขาหนึ่ง GPIO27 อีกขา GND กด = คนผ่าน) โค้ดไม่ต้องแก้ และบอกในวิดีโอว่าเป็นตัวแทนชั่วคราว

## 6. ทำไมแผนนี้ทำทันในเวลาที่มี

- **โค้ดหลักเสร็จแล้ว:** ก่อน checkpoint แต่ละคนแค่ต่อสาย ตั้งค่า แฟลช และทดสอบ ใช้เวลาจริงคนละประมาณ 5–7 ชั่วโมงใน 4 วัน
- **ทดสอบคนเดียวได้โดยไม่ต้องรอใคร:**
  - node ทดสอบกับ "บอร์ดรับทดสอบ" (ใช้บอร์ดตัวที่ 2 ชั่วคราว)
  - gateway ทดสอบด้วยโหมด `gateway_fake` ที่สร้างข้อมูล node ปลอมเอง
  - dashboard และ AI ทดสอบด้วย `fake_gateway.py`
  - วันศุกร์จึงเหลือแค่เสียบต่อกันจริง (ประมาณ 1–2 ชั่วโมง)
- **ฟีเจอร์ E-items (FreeRTOS, buffer, TLS, OTA) อยู่ในโค้ด gateway แล้ว** หลัง checkpoint เป็นงานทดสอบ เปิดใช้ และทำความเข้าใจ ไม่ใช่เขียนใหม่
- **AI ใช้โมเดลสำเร็จรูป (Chronos-2) ไม่ต้องเทรนเอง** จึงไม่ต้องรอเก็บข้อมูลหลายวัน: เริ่มเก็บข้อมูลจริงวันเสาร์ 21 พอครบ 24 ชม. ก็วัดผลได้ (จ. 23) และเปิด AI คุมพัดลมได้ตั้งแต่อังคาร 24 แล้ววัดผลซ้ำด้วยข้อมูลทั้งหมดช่วง 30 พ.ย.–3 ธ.ค.

**ความเสี่ยงที่ควรรู้:**
- **NETPIE:** ผมยืนยันจากเอกสารได้แค่ port, topic, schema และ timestamp แต่หน้าตาเมนูในเว็บอาจไม่ตรงกับที่เขียนทุกจุด ถ้าเจอให้เทียบกับ docs.netpie.io
- **ระยะของ KY-032:** ตรวจจับได้ใกล้ (ปรับได้ประมาณ 2–30 ซม.) ในห้องน้ำจริงต้องติดตรงทางเดินแคบที่คนเดินผ่านใกล้เซ็นเซอร์ ดูไฟล์ 02 ขั้นที่ 9 และแสงแดดจัดทำให้ทำงานผิดพลาดได้ (เป็นเซ็นเซอร์อินฟราเรด)
- **Compile:** โค้ด firmware ผ่านการ compile แล้ว แต่ยังไม่ได้รันบนบอร์ดจริง ค่าเกณฑ์ (เช่นค่าพื้นเปียก) ต้องปรับตามอุปกรณ์จริงตามขั้นตอนในแต่ละไฟล์

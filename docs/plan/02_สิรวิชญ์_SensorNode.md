# 02 — สิรวิชญ์: Embedded Developer (Sensor Node)

อ่าน `00_ภาพรวม_ทุกคนอ่านก่อน.md` ข้อ 2 และ 3 ก่อน

## สิ่งที่ต้องส่งมอบ

- **Sensor node 2 ตัว** ใช้ firmware เดียวกัน (ต่างกันแค่ env ใน `platformio.ini`):
  - **WC-1 (ประตู):** KY-032 (นับคนเข้า) + Ultrasonic HC-SR04 (ดูว่ามีคนอยู่ในห้องไหม) — ทำเป็น**บอร์ดตัวแรก**
  - **WC-2 (พื้น):** Water level module (ตรวจพื้นเปียก) — บอร์ดตัวที่ 2
- KY-032 คือเซ็นเซอร์อินฟราเรดแบบสะท้อน ยืมจากรายการอุปกรณ์ของวิชา ติดที่ทางเข้าจุดเดียว (ไม่มีการนับคนที่โซนโถ)
- MQ-137 กับ KY-015 อยู่ที่ gateway เป็นงานของสุรสิทธิ์ node ไม่ต้องยุ่งกับค่ากลิ่น
- ส่งข้อมูลให้ gateway ทุก 10 วินาที ถ้าส่งไม่ถึงจะส่งซ้ำ และหา channel ใหม่เองเมื่อ hotspot เปลี่ยน
- ได้คะแนน: **Scalability 3/3** (node จริง 2 ตัว), **E2** (นับคนด้วย ISR), **E4 ฝั่ง node** (ACK + retry)

ไฟล์ของคุณใน starter code: `firmware/sensor-node/` (`platformio.ini`, `include/config.h`, `src/main.cpp`)

## ขั้นที่ 2: ต่อและทดสอบ ultrasonic และ water level (จ. 16)

### 2.1 Ultrasonic HC-SR04 (ลงบอร์ดตัวแรก = WC-1 ประตู)

```
Ultrasonic VCC ──────────────── ESP32 VIN (หรือขาที่เขียน 5V)
Ultrasonic GND ──────────────── ESP32 GND
Ultrasonic Trig ─────────────── ESP32 GPIO26
Ultrasonic Echo ──[10kΩ]──┬──── ESP32 GPIO33
                          │
                        [20kΩ]
                          │
                         GND
```

**ทำไมขา Echo ต้องมีตัวต้านทาน:** ultrasonic ใช้ไฟ 5 V ขา Echo จึงปล่อยออกมา 5 V แต่ขา ESP32 รับได้สูงสุด 3.3 V ตัวต้านทานแบ่งแรงดันเหลือ 5 × 20/(10+20) = 3.33 V ส่วนขา Trig รับ 3.3 V จาก ESP32 ได้ ต่อตรงได้เลย ถ้าไม่มี 20kΩ ใช้ 10kΩ สองตัวต่ออนุกรมแทนได้

### 2.2 Water level module (ลงบอร์ดตัวที่ 2 = WC-2 พื้น)

```
Water level + ──────────────── ESP32 3.3V
Water level − ──────────────── ESP32 GND
Water level S ──────────────── ESP32 GPIO35
```

ใช้ไฟ 3.3 V ขา S ออกไม่เกิน 3.3 V ต่อตรงได้ ไม่ต้องมี divider

### 2.3 ทดสอบทั้งสองตัว

ใช้ `src/main.cpp` ของ hwtest เป็น:
```cpp
#include <Arduino.h>
#define US_TRIG_PIN 26
#define US_ECHO_PIN 33
#define LEAK_PIN    35

int readDistanceCm() {
  digitalWrite(US_TRIG_PIN, LOW);  delayMicroseconds(2);
  digitalWrite(US_TRIG_PIN, HIGH); delayMicroseconds(10);
  digitalWrite(US_TRIG_PIN, LOW);
  unsigned long us = pulseIn(US_ECHO_PIN, HIGH, 30000);  // รอไม่เกิน 30 ms
  if (us == 0) return -1;                                // ไม่มีเสียงสะท้อนกลับ
  return (int)(us / 58);                                 // แปลงเวลาเป็น ซม.
}

void setup() {
  Serial.begin(115200);
  pinMode(US_TRIG_PIN, OUTPUT);
  pinMode(US_ECHO_PIN, INPUT);
  analogSetPinAttenuation(LEAK_PIN, ADC_11db);
}
void loop() {
  Serial.printf("dist=%d cm   leak_adc=%d\n", readDistanceCm(), analogRead(LEAK_PIN));
  delay(500);
}
```

| ทดสอบ | ผลที่ต้องได้ |
| --- | --- |
| Ultrasonic หันไปทางผนังที่วัดด้วยตลับเมตรได้ 100 ซม. | ค่าประมาณ 95–105 (ถ้าขึ้น −1 ตลอด = Echo/Trig สลับกัน หรือ divider ต่อผิด) |
| Ultrasonic เอามือบังห่าง 30 ซม. | ค่าประมาณ 30 |
| Water level แห้ง | ค่าประมาณ 0–300 → **จดไว้** |
| Water level แตะฟองน้ำเปียก | ค่าประมาณ 1500–3000 → **จดไว้** |

เอาค่าแห้งกับค่าเปียกมาหาค่ากลาง เก็บไว้ใส่ `LEAK_THRESHOLD` ใน `include/config.h` ตอนขั้นที่ 4 (เช่น แห้ง 200 เปียก 2000 → ใส่ 1000)

- ถ้ายังไม่ได้ยืม ultrasonic หรือ water level ข้ามไปทำขั้นที่ 3 ก่อนได้ โค้ดจะข้ามเซ็นเซอร์ที่ไม่ได้เปิดใน `platformio.ini` เอง

## ขั้นที่ 3: ต่อและทดสอบ KY-032 (อ. 17)

KY-032 คือเซ็นเซอร์อินฟราเรดแบบสะท้อน (มีหลอดส่ง IR และตัวรับอยู่บนแผงเดียวกัน) เมื่อมีสิ่งของหรือคนเข้ามาใกล้หน้าเซ็นเซอร์ แสง IR จะสะท้อนกลับ ขา OUT จะเปลี่ยนเป็น **LOW** และไฟ LED บนแผงจะติด ใช้แทน IR break-beam ได้เพราะให้สัญญาณ HIGH/LOW แบบเดียวกัน โค้ด ISR เดิมใช้ได้เลย

**ขาของ KY-032 (เรียงตามที่พิมพ์บนแผง):**
```
EN   → ไม่ต้องต่อ (ต้องเสียบ jumper ตรงคำว่า EN ไว้ เซ็นเซอร์จะทำงานตลอดเวลา)
+    → 3.3V
GND  → GND
OUT  → GPIO27
```
- ใช้ไฟ 3.3 V ได้ ขา OUT จึงออกไม่เกิน 3.3 V ต่อเข้า ESP32 ตรงได้เลย ไม่ต้องมี divider
- บนแผงมี potentiometer 2 ตัว: ตัวหนึ่งปรับ**ระยะตรวจจับ** อีกตัวปรับความถี่ของ IR ปกติไม่ต้องยุ่งตัวความถี่ ถ้าไม่แน่ใจว่าตัวไหน ให้ค่อยๆ หมุนทีละตัวแล้วดูว่าระยะที่ไฟ LED ติดเปลี่ยนไหม
- ถ้าไม่มี jumper ที่ EN (ไฟ LED ไม่ติดเลยแม้เอามือบัง) ให้ต่อขา EN → GND แทน

**ทดสอบ:**
```cpp
#include <Arduino.h>
#define BEAM_PIN 27
int last = -1;
void setup() {
  Serial.begin(115200);
  pinMode(BEAM_PIN, INPUT_PULLUP);
}
void loop() {
  int s = digitalRead(BEAM_PIN);
  if (s != last) {
    Serial.println(s == LOW ? "LOW  (something in front)" : "HIGH (clear)");
    last = s;
  }
  delay(5);
}
```
1. แฟลชโค้ดนี้ เปิด Serial Monitor
2. เอามือเข้าไปห่างหน้าเซ็นเซอร์ประมาณ 10 ซม. ต้องขึ้น **LOW** และไฟ LED บนแผงติด เอามือออกต้องขึ้น **HIGH**
3. **ปรับระยะ:** หมุน potentiometer ตัวปรับระยะด้วยไขควงเล็ก จนเอามือที่ระยะ 20 ซม. แล้ว LED ติด และเอามือไกลกว่า 30 ซม. แล้ว LED ดับ (KY-032 ตรวจได้ไกลสุดประมาณ 30–40 ซม. ห้ามหวังระยะไกลกว่านี้)
4. หันเซ็นเซอร์ไปทางผนังว่างที่ไกลเกิน 50 ซม. ต้องขึ้น HIGH ค้างไว้ ถ้า LOW ค้าง แปลว่าระยะตั้งไกลเกินไป หรือมีแสงแดดส่องเข้าเซ็นเซอร์ ให้หมุนลดระยะ
5. ถ้ายังไม่ได้ยืม KY-032 ใช้ปุ่มกดแทน: ขาหนึ่ง → GPIO27, อีกขา → GND กดแล้วต้องขึ้น LOW

### โค้ดทำงานยังไง (เปิด `src/main.cpp` อ่านคู่กัน)

| ส่วน | ฟังก์ชัน | ทำอะไร |
| --- | --- | --- |
| 1 | `onBeamBreak()` | **ISR** ทำงานทันทีที่ขา GPIO27 เปลี่ยนจาก HIGH เป็น LOW เพิ่มตัวนับ `beamCount` ทีละ 1 ถ้าห่างจากครั้งก่อนเกิน 500 ms (debounce: คนหนึ่งคนเดินผ่าน สัญญาณอาจกระพริบหลายครั้ง) ใน ISR ห้าม `Serial.print`/`delay` เพราะต้องจบเร็ว |
| 1 | `takeBeamCount()` | ดึงค่าตัวนับออกมาแล้วรีเซ็ตเป็น 0 ทำนอก ISR (= **deferred processing**) ใช้ `portENTER_CRITICAL` กันไม่ให้ ISR แทรกตอนกำลังอ่าน |
| 1 | `returnBeamCount()` | ถ้าส่งไม่ถึง gateway คืนจำนวนคนกลับเข้าตัวนับ จะได้ส่งรอบหน้า ไม่หาย |
| 2 | `readDistanceCm()` | ส่งพัลส์ออกขา Trig แล้วจับเวลาที่ขา Echo กลับมา หารด้วย 58 เป็นเซนติเมตร คืน −1 ถ้าไม่มีเสียงสะท้อนกลับใน 30 ms |
| 3 | `readLeak()` | อ่าน ADC ของ water level ถ้าเกิน `LEAK_THRESHOLD` คืน 1 (พื้นเปียก) |
| 3 | `scanForChannel()` | scan หา Wi-Fi ชื่อ `WIFI_SSID` แล้วคืนเลข channel (node ไม่ได้ต่อ Wi-Fi แค่ต้องรู้ channel) |
| 3 | `startEspNow()` | ตั้ง channel ให้ตรงกับ gateway, เปิด ESP-NOW, ลงทะเบียน MAC ของ gateway เป็น peer |
| 3 | `onDataSent()` | ESP-NOW เรียกหลังส่ง บอกว่า gateway ตอบรับ (**ACK**) หรือไม่ |
| 3 | `sendWithRetry()` | ส่ง แล้วรอผลไม่เกิน 100 ms ถ้าไม่ได้ ACK ส่งซ้ำ รวมไม่เกิน 4 ครั้ง และรอนานขึ้นทุกครั้ง |
| 5 | `buildAndSend()` | สร้าง JSON จากเซ็นเซอร์ที่บอร์ดนี้มี แล้วส่ง ถ้าส่งไม่สำเร็จคืนจำนวนคนกลับเข้าตัวนับ |
| 5 | `loop()` | อ่านเซ็นเซอร์ทุก 0.5 วินาที และส่งทุก 10 วินาที **ถ้าค่า leak เปลี่ยน (เปียก↔แห้ง) จะส่งทันทีไม่รอครบรอบ** เพื่อให้แจ้งเตือนพื้นเปียกทัน |
| config | `HAS_BEAM` / `HAS_ULTRASONIC` / `HAS_LEAK` | กำหนดใน `platformio.ini`: `env:wc1` เปิด KY-032 + ultrasonic, `env:wc2` เปิด water level อย่างเดียว ใช้ firmware ไฟล์เดียวกันทั้งสองบอร์ด |

## ขั้นที่ 5: ทดสอบ ESP-NOW ด้วยบอร์ดรับทดสอบ (พ. 18)

ยังไม่ต้องรอ gateway ใช้บอร์ดตัวที่ 2 ของคุณเป็นตัวรับชั่วคราว

1. เปิด hotspot ชื่อ `OnBed-Hotspot`
2. ใน hwtest ใส่โค้ดนี้แล้วแฟลชลง**บอร์ดตัวที่ 2**:
   ```cpp
   #include <Arduino.h>
   #include <WiFi.h>
   #include <esp_now.h>
   const char *SSID = "OnBed-Hotspot";   // ชื่อ hotspot เดียวกับใน config.h
   const char *PASS = "your-password";
   void onRecv(const uint8_t *mac, const uint8_t *data, int len) {
     Serial.printf("from %02X:%02X:%02X:%02X:%02X:%02X  %.*s\n",
                   mac[0], mac[1], mac[2], mac[3], mac[4], mac[5], len, (const char *)data);
   }
   void setup() {
     Serial.begin(115200);
     WiFi.mode(WIFI_STA);
     WiFi.setSleep(false);
     WiFi.begin(SSID, PASS);
     while (WiFi.status() != WL_CONNECTED) delay(300);
     Serial.printf("Test receiver MAC: %s  channel: %d\n", WiFi.macAddress().c_str(), WiFi.channel());
     esp_now_init();
     esp_now_register_recv_cb(onRecv);
   }
   void loop() {}
   ```
3. ดู Serial ของบอร์ดตัวที่ 2 จด `Test receiver MAC` แล้วใส่ใน `GATEWAY_MAC` ของ node (`config.h`) แปลง `24:6F:28:AA:BB:CC` เป็น `{0x24, 0x6F, 0x28, 0xAA, 0xBB, 0xCC}`
4. แฟลช node (`env:wc1`) ลง**บอร์ดตัวแรก**
5. **ผลที่ต้องเห็น:**
   - Serial ของ node: `ESP-NOW ready on channel 6` แล้วทุก 10 วินาที `{"node_id":"WC-1","seq":0,"people":0,"occupied":0,"dist_cm":152}  OK`
   - Serial ของตัวรับ: `from 24:..  {"node_id":"WC-1",...}`
   - เอามือผ่านหน้า KY-032 หลายครั้ง (เว้นแต่ละครั้งเกิน 1 วินาที) ค่า `people` รอบถัดไปต้องเท่าจำนวนครั้ง
6. **ทดสอบ retry:** ถอดสายตัวรับ node ต้องขึ้น `send failed (attempt 1/4)` ... `FAILED` ครบ 3 รอบแล้วขึ้น `rescanning channel` เสียบตัวรับกลับ ต้องกลับมา `OK` เอง
7. ถ้าไม่ขึ้น `OK` ดูตารางแก้ปัญหาในข้อ 14

## ขั้นที่ 8: ตั้งค่า OCCUPIED_CM และ LEAK_THRESHOLD ตามห้องจริง (ส. 21)

ค่าสองตัวนี้ขึ้นกับว่าติดเซ็นเซอร์ตรงไหน ค่าที่ตั้งมาในโค้ดเป็นค่าเริ่มต้นเฉยๆ ต้องวัดของจริงแล้วตั้งใหม่ (และตั้งใหม่อีกครั้งตอนย้ายเข้าห้องจำลอง ขั้นที่ 12)

**ดูค่าที่เซ็นเซอร์อ่านได้ยังไง:** เสียบ USB จาก node เข้าโน้ตบุ๊ก เปิด PlatformIO → กดไอคอนปลั๊ก (Serial Monitor) node จะพิมพ์ข้อความที่ส่งออกไปทุก 10 วินาที ตัวเลขที่ต้องดูอยู่ในบรรทัดนั้น เช่น

```
{"node_id":"WC-1","seq":12,"people":0,"occupied":0,"dist_cm":152}  OK
```

`dist_cm` คือระยะที่ ultrasonic วัดได้ และ `occupied` คือผลสรุปว่ามีคนอยู่ไหม ถ้าไม่อยากรอ 10 วินาที ดูบน dashboard ที่วัตตะนะทำก็ได้ ค่าเดียวกัน

---

### 8.1 ตั้ง OCCUPIED_CM (ultrasonic ที่ node WC-1)

หลักการ: ถ้าระยะที่วัดได้ **น้อยกว่า** `OCCUPIED_CM` แปลว่ามีอะไรมาบังอยู่ = มีคน เราจึงต้องตั้งค่าให้อยู่กึ่งกลางระหว่าง "ระยะตอนห้องว่าง" กับ "ระยะตอนมีคนยืน"

1. ติด node WC-1 เข้าที่เรียบร้อยก่อน (ขั้นที่ 9) แล้วเสียบ USB เปิด Serial Monitor
2. **ตอนห้องว่าง ไม่มีใครยืนอยู่** อ่านค่า `dist_cm` สัก 3 รอบ จดไว้ สมมติได้ 150, 151, 150 → ใช้ **150**
3. ให้เพื่อนไปยืนตรงจุดที่คนใช้ห้องน้ำยืนจริง อ่านค่า `dist_cm` อีก 3 รอบ สมมติได้ 44, 46, 45 → ใช้ **45**
4. หาค่ากลาง: (150 + 45) ÷ 2 ≈ **97** ปัดเป็นเลขกลมๆ ใช้ **90** ก็ได้ (เอียงไปทางค่าน้อยกว่าเล็กน้อยจะปลอดภัยกว่า เพราะกันไม่ให้ไฟติดเองตอนห้องว่าง)
5. เปิด `firmware/sensor-node/include/config.h` หาบรรทัด
   ```cpp
   #define OCCUPIED_CM     60    // ultrasonic วัดได้ใกล้กว่านี้ = มีคนยืนอยู่ (ตั้งใหม่ตามห้องจริง)
   ```
   แก้เลข `60` เป็นค่าที่คำนวณได้ แล้วบันทึก
6. เลือก env **`env:wc1`** แล้วกด Upload ใหม่
7. **ทดสอบ:** ยืนตรงจุดนั้น ภายใน 1 รอบส่ง (10 วินาที) `occupied` ต้องเป็น `1` เดินออกมา ต้องกลับเป็น `0`
   - ถ้า `occupied` เป็น 1 ตลอดแม้ไม่มีคน แปลว่าเซ็นเซอร์หันไปชนผนังที่ใกล้เกินไป ให้หันเซ็นเซอร์ใหม่หรือลดค่า `OCCUPIED_CM` ลง
   - ถ้าเป็น 0 ตลอดแม้มีคนยืน แปลว่าค่าที่ตั้งน้อยเกินไป ให้เพิ่มขึ้น
   - ถ้า `dist_cm` เป็น 0 ตลอด แปลว่า ultrasonic ไม่ทำงาน ดูตารางแก้ปัญหาข้อ 14

### 8.2 ตั้ง LEAK_THRESHOLD (water level ที่ node WC-2)

หลักการ: แผ่นเซ็นเซอร์ยิ่งเปียกยิ่งนำไฟฟ้าได้ดี ค่า ADC ยิ่งสูง เราตั้งเส้นแบ่งไว้ระหว่าง "ค่าตอนแห้ง" กับ "ค่าตอนเปียก"

1. วางแผ่นเซ็นเซอร์ตรงจุดที่น้ำขังบ่อยจริง ในสภาพ**พื้นแห้ง**
2. ค่า ADC ดิบไม่ได้ถูกส่งออกมาในข้อความปกติ ให้ดูจาก `leak` แทน (0 = แห้ง) ถ้าอยากเห็นตัวเลขดิบ ให้แฟลชสเก็ตช์ทดสอบของขั้นที่ 2.3 ลงไปชั่วคราว แล้วอ่านค่า `leak_adc` สมมติพื้นแห้งได้ **180**
3. ราดน้ำบางๆ หรือวางฟองน้ำเปียกลงบนแผ่น อ่านค่าอีกครั้ง สมมติได้ **1950**
4. หาค่ากลาง: (180 + 1950) ÷ 2 ≈ **1065** ปัดเป็น **1000**
5. เปิด `firmware/sensor-node/include/config.h` หาบรรทัด
   ```cpp
   #define LEAK_THRESHOLD  1000  // ค่า ADC มากกว่านี้ = พื้นเปียก (หาค่ากลางระหว่างแห้งกับเปียก)
   ```
   แก้เลขเป็นค่าที่คำนวณได้ แล้วบันทึก
6. เลือก env **`env:wc2`** แล้วกด Upload ใหม่
7. **ทดสอบ:** วางฟองน้ำเปียกบนแผ่น node ต้องพิมพ์ข้อความใหม่ออกมา**ทันที**พร้อมคำว่า `(leak!)` ไม่ต้องรอครบ 10 วินาที เอาฟองน้ำออกแล้วเช็ดให้แห้ง ต้องได้ `(dry)`
   - ถ้า `leak` เป็น 1 ตลอดทั้งที่แห้ง แปลว่าค่าที่ตั้งต่ำเกินไป หรือแผ่นยังชื้นอยู่ เช็ดให้แห้งสนิทแล้ววัดใหม่
   - ถ้าวางฟองน้ำแล้วไม่เปลี่ยนเป็น 1 แปลว่าค่าที่ตั้งสูงเกินไป ให้ลดลง

- **ระยะสำคัญมาก:** KY-032 ตรวจจับได้แค่ประมาณ 30 ซม. (ตามที่ปรับในขั้นที่ 3) คนต้องเดินผ่านใกล้เซ็นเซอร์ จึงต้องติดที่**จุดแคบที่สุด** ที่ทุกคนต้องเดินผ่าน เช่น ขอบประตู หรือช่องระหว่างผนังกับอ่างล้างมือ
  - ทดสอบก่อนติดถาวร: ถือเซ็นเซอร์ไว้ที่จุดนั้น ให้เพื่อนเดินผ่านแบบปกติ 5 ครั้ง (ทั้งชิดเซ็นเซอร์และเดินกลางทาง) LED ต้องติดทุกครั้ง ถ้าเดินกลางทางแล้วไม่ติด ให้หมุนเพิ่มระยะ หรือย้ายไปจุดที่แคบกว่า
  - ห้ามหันเซ็นเซอร์ไปทางผนังฝั่งตรงข้ามที่อยู่ใกล้กว่าระยะที่ตั้ง (LED จะติดค้าง นับไม่ได้) และหลีกเลี่ยงจุดที่แดดส่องตรง เพราะแสงแดดมีอินฟราเรดทำให้อ่านผิด
- ติดกล่องสูงจากพื้นอย่างน้อย 1 เมตร ห่างอ่างและโถ (กฎความปลอดภัยเรื่องแยกน้ำกับวงจร) ใช้เทปกาวสองหน้าแบบแรงหรือเคเบิลไทร์
- ไฟเลี้ยง: สาย USB ยาว + หัวชาร์จมือถือ 5V 1A ขึ้นไป
- หลังติดเสร็จ เปิด dashboard บนมือถือ เดินผ่าน KY-032 ของแต่ละโซน 5 ครั้ง ต้องเห็นจำนวนคนเพิ่มทั้ง 2 โซน

## ข้อ 16: คำถามที่อาจารย์น่าจะถาม (เตรียมตอบให้ได้)

1. **ISR คืออะไร ทำไมห้าม print ใน ISR?** ISR ขัดจังหวะโปรแกรมหลักทันที ต้องจบเร็วที่สุด `Serial.print` ช้าและอาจค้าง จึงทำแค่เพิ่มตัวนับ ส่วนการส่งข้อมูลทำทีหลังใน loop
2. **ทำไมตัวแปรต้องเป็น `volatile`?** บอก compiler ว่าค่าอาจเปลี่ยนจาก ISR ได้ตลอด ห้ามเก็บค่าเก่าไว้ใน register
3. **Debounce ทำไม?** คนเดินผ่านหนึ่งครั้ง สัญญาณ KY-032 อาจเปลี่ยนหลายครั้ง (แขน ลำตัว กระเป๋าผ่านทีละส่วน) จึงไม่นับซ้ำภายใน 500 ms
4. **ทำไมต้องรู้ channel ของ hotspot?** ESP-NOW ส่งได้เฉพาะคลื่น channel เดียวกัน gateway ต่อ hotspot จึงถูกบังคับให้อยู่ channel ของ hotspot node จึงต้อง scan หา channel นั้น
5. **ACK ของ ESP-NOW มาจากไหน?** ESP-NOW แบบ unicast มีการตอบรับระดับ MAC ในตัว callback `onDataSent` บอกว่า gateway ได้รับหรือไม่
6. **ทำไม node WC-2 ส่งทันทีตอนพื้นเปียก ไม่รอครบ 10 วินาที?** พื้นเปียกเป็นเหตุการณ์ที่ต้องแจ้งเร็ว ถ้ารอรอบส่งปกติอาจช้าได้ถึง 10 วินาทีก่อนที่ gateway จะรู้ จึงส่งทันทีเมื่อค่าเปลี่ยนจากแห้งเป็นเปียกหรือกลับกัน ส่วนรอบ 10 วินาทีตามปกติยังส่งอยู่เพื่อให้นับ packet delivery rate ได้
7. **รองรับ node มากกว่า 2 ตัวไหม?** ได้ แค่แฟลชด้วย `NODE_ID` ใหม่ gateway ลงทะเบียน node ใหม่อัตโนมัติ (สูงสุด 4)
8. **ทำไมใช้ KY-032 แทน IR break-beam?** เป็นเซ็นเซอร์ที่ยืมได้จากวิชา ให้สัญญาณ HIGH/LOW แบบเดียวกัน (LOW เมื่อมีคนผ่าน) โค้ด ISR เหมือนเดิม ข้อดีคือติดฝั่งเดียวไม่ต้องเล็งตัวส่งกับตัวรับให้ตรงกัน ข้อจำกัดคือระยะสั้น (~30 ซม.) จึงต้องติดที่จุดแคบ และแสงแดดรบกวนได้
9. **ทำไมนับคนแค่ที่ประตู?** ประตูเป็นจุดเดียวที่ทุกคนต้องเดินผ่าน นับที่นี่ได้จำนวนผู้ใช้ห้องน้ำครบแล้ว การเพิ่มจุดนับข้างในจะนับคนเดิมซ้ำ ส่วนการรู้ว่ามีคนอยู่ในห้องตอนนี้ไหมใช้ ultrasonic แทน ซึ่งตรวจคนที่ยืนนิ่งได้ด้วย
10. **ทำไมเซ็นเซอร์กระจายแบบนี้?** เซ็นเซอร์ที่ต้องใช้ตัดสินใจทันที (MQ-137 ที่ใช้คุมพัดลม) อยู่ที่ gateway จึงไม่ต้องรอข้อความจาก node ส่วนเซ็นเซอร์ที่ต้องอยู่ตามจุด (ประตู พื้น) อยู่บน node แล้วส่งผ่าน ESP-NOW

## สิ่งที่ต้องส่งมอบ

- **Sensor node 2 ตัว** ใช้ firmware เดียวกัน (ต่างกันแค่ env ใน `platformio.ini`):
  - **WC-2 (โซนโถ):** MQ-137 (วัดกลิ่น) + KY-032 (นับคน) — ทำเป็น**บอร์ดตัวแรก**
  - **WC-1 (โซนทางเข้า):** KY-032 (นับคน) อย่างเดียว — บอร์ดตัวที่ 2

- ได้คะแนน: **Scalability 3/3** (node จริง 2 ตัว), **E2** (นับคนด้วย ISR), **E4 ฝั่ง node** (ACK + retry)

## ขั้นที่ 2: ต่อและทดสอบ MQ-137 (จ. 16)

ต่อ MQ-137 กับ**บอร์ดตัวแรก** (บอร์ดนี้จะเป็น WC-2 โซนโถ)

**ต่อสาย** (บอร์ด ESP32 ต้องเสียบ USB อยู่ ขา VIN/5V จะมีไฟ 5 V):

```
MQ-137 VCC ──────────────── ESP32 VIN (หรือขาที่เขียน 5V)
MQ-137 GND ──────────────── ESP32 GND
MQ-137 AO ──[10kΩ]──┬────── ESP32 GPIO34
                    │
                  [20kΩ]
                    │
                   GND
MQ-137 DO   (ไม่ต้องต่อ)
```

**ทำไมต้องมีตัวต้านทาน 2 ตัว (voltage divider):** โมดูล MQ ใช้ไฟ 5 V ขา AO จึงออกได้สูงสุด 5 V แต่ขา ESP32 รับได้สูงสุด 3.3 V ถ้าต่อตรงอาจทำให้ขาเสีย ตัวต้านทานแบ่งแรงดันให้เหลือ 5 × 20/(10+20) = 3.33 V ในโค้ดจึงคูณกลับด้วย 1.5

**ทดสอบ:** ใช้ `src/main.cpp` ของ hwtest เป็น:
```cpp
#include <Arduino.h>
#define MQ_PIN 34
void setup() {
  Serial.begin(115200);
  analogSetPinAttenuation(MQ_PIN, ADC_11db);
}
void loop() {
  uint32_t mv = analogReadMilliVolts(MQ_PIN);
  Serial.printf("pin=%u mV  ->  AO=%.2f V\n", mv, mv / 1000.0 * 1.5);
  delay(500);
}
```
- ช่วงแรกค่าจะสูงแล้วค่อยๆ ลด เพราะ heater ในเซ็นเซอร์กำลังอุ่นเครื่อง (ปกติ 3–5 นาที)
- ลองเปิดขวดน้ำยาเช็ดกระจก (มีแอมโมเนีย) ใกล้ๆ ค่า AO ต้อง**เพิ่มขึ้น**
- **MQ-137 ใหม่ต้อง burn-in:** เสียบไฟทิ้งไว้ 24–48 ชั่วโมงครั้งแรก ค่าถึงจะนิ่ง ทำคืนนี้ได้เลย (เสียบ USB กับหัวชาร์จทิ้งไว้ บอร์ดไม่ต้องรันอะไร)
- ถ้ายังไม่มี MQ-137 ใช้ potentiometer: ขากลาง → GPIO34, ขาข้าง → 3.3V และ GND (**ไม่ต้องใช้ divider** เพราะไม่เกิน 3.3 V) หมุนแล้วค่าต้องเปลี่ยน

## ขั้นที่ 3: ต่อและทดสอบ KY-032 (อ. 17)

KY-032 คือเซ็นเซอร์อินฟราเรดแบบสะท้อน (มีหลอดส่ง IR และตัวรับอยู่บนแผงเดียวกัน) เมื่อมีสิ่งของหรือคนเข้ามาใกล้หน้าเซ็นเซอร์ แสง IR จะสะท้อนกลับ ขา OUT จะเปลี่ยนเป็น **LOW** และไฟ LED บนแผงจะติด ใช้แทน IR break-beam ได้เพราะให้สัญญาณ HIGH/LOW แบบเดียวกัน โค้ด ISR เดิมใช้ได้เลย

**ขาของ KY-032 (เรียงตามที่พิมพ์บนแผง):**
```
EN   → ไม่ต้องต่อ (ต้องเสียบ jumper ตรงคำว่า EN ไว้ เซ็นเซอร์จะทำงานตลอดเวลา)
+    → 3.3V
GND  → GND
OUT  → GPIO27
```
- ใช้ไฟ 3.3 V ได้ ขา OUT จึงออกไม่เกิน 3.3 V ต่อเข้า ESP32 ตรงได้เลย ไม่ต้องมี divider
- บนแผงมี potentiometer 2 ตัว: ตัวหนึ่งปรับ**ระยะตรวจจับ** อีกตัวปรับความถี่ของ IR ปกติไม่ต้องยุ่งตัวความถี่ ถ้าไม่แน่ใจว่าตัวไหน ให้ค่อยๆ หมุนทีละตัวแล้วดูว่าระยะที่ไฟ LED ติดเปลี่ยนไหม
- ถ้าไม่มี jumper ที่ EN (ไฟ LED ไม่ติดเลยแม้เอามือบัง) ให้ต่อขา EN → GND แทน

**ทดสอบ:**
```cpp
#include <Arduino.h>
#define BEAM_PIN 27
int last = -1;
void setup() {
  Serial.begin(115200);
  pinMode(BEAM_PIN, INPUT_PULLUP);
}
void loop() {
  int s = digitalRead(BEAM_PIN);
  if (s != last) {
    Serial.println(s == LOW ? "LOW  (something in front)" : "HIGH (clear)");
    last = s;
  }
  delay(5);
}
```
1. แฟลชโค้ดนี้ เปิด Serial Monitor
2. เอามือเข้าไปห่างหน้าเซ็นเซอร์ประมาณ 10 ซม. ต้องขึ้น **LOW** และไฟ LED บนแผงติด เอามือออกต้องขึ้น **HIGH**
3. **ปรับระยะ:** หมุน potentiometer ตัวปรับระยะด้วยไขควงเล็ก จนเอามือที่ระยะ 20 ซม. แล้ว LED ติด และเอามือไกลกว่า 30 ซม. แล้ว LED ดับ (KY-032 ตรวจได้ไกลสุดประมาณ 30–40 ซม. ห้ามหวังระยะไกลกว่านี้)
4. หันเซ็นเซอร์ไปทางผนังว่างที่ไกลเกิน 50 ซม. ต้องขึ้น HIGH ค้างไว้ ถ้า LOW ค้าง แปลว่าระยะตั้งไกลเกินไป หรือมีแสงแดดส่องเข้าเซ็นเซอร์ ให้หมุนลดระยะ
5. ถ้ายังไม่ได้ยืม KY-032 ใช้ปุ่มกดแทน: ขาหนึ่ง → GPIO27, อีกขา → GND กดแล้วต้องขึ้น LOW

### โค้ดทำงานยังไง (เปิด `src/main.cpp` อ่านคู่กัน)

| ส่วน | ฟังก์ชัน | ทำอะไร |
| --- | --- | --- |
| 1 | `onBeamBreak()` | **ISR** ทำงานทันทีที่ขา GPIO27 เปลี่ยนจาก HIGH เป็น LOW เพิ่มตัวนับ `beamCount` ทีละ 1 ถ้าห่างจากครั้งก่อนเกิน 500 ms (debounce: คนหนึ่งคนเดินผ่าน สัญญาณอาจกระพริบหลายครั้ง) ใน ISR ห้าม `Serial.print`/`delay` เพราะต้องจบเร็ว |
| 1 | `takeBeamCount()` | ดึงค่าตัวนับออกมาแล้วรีเซ็ตเป็น 0 ทำนอก ISR (= **deferred processing**) ใช้ `portENTER_CRITICAL` กันไม่ให้ ISR แทรกตอนกำลังอ่าน |
| 1 | `returnBeamCount()` | ถ้าส่งไม่ถึง gateway คืนจำนวนคนกลับเข้าตัวนับ จะได้ส่งรอบหน้า ไม่หาย |
| 2 | `readSensorVolt()` | อ่าน ADC 20 ครั้งแล้วเฉลี่ย คูณ 1.5 กลับเป็นแรงดันจริงที่ขา AO |
| 2 | `readOdor()` | คำนวณ Rs = (5 − V)/V แล้วคืน **R0/Rs** (อากาศสะอาด ≈ 1, มีแอมโมเนีย Rs ลดลง → ค่าเพิ่มขึ้น) ถ้าแรงดัน < 0.05 V ถือว่าสายหลุด คืน −1 |
| 3 | `scanForChannel()` | scan หา Wi-Fi ชื่อ `WIFI_SSID` แล้วคืนเลข channel (node ไม่ได้ต่อ Wi-Fi แค่ต้องรู้ channel) |
| 3 | `startEspNow()` | ตั้ง channel ให้ตรงกับ gateway, เปิด ESP-NOW, ลงทะเบียน MAC ของ gateway เป็น peer |
| 3 | `onDataSent()` | ESP-NOW เรียกหลังส่ง บอกว่า gateway ตอบรับ (**ACK**) หรือไม่ |
| 3 | `sendWithRetry()` | ส่ง แล้วรอผลไม่เกิน 100 ms ถ้าไม่ได้ ACK ส่งซ้ำ รวมไม่เกิน 4 ครั้ง และรอนานขึ้นทุกครั้ง |
| 4 | `loop()` | ทุก 10 วินาที: ดึงจำนวนคน, อ่านกลิ่น (เฉพาะ `HAS_MQ=1`), สร้าง JSON, ส่ง, `seq++` ถ้าล้มเหลวติดกัน 3 รอบ → scan หา channel ใหม่ |
| config | `HAS_MQ` | กำหนดใน `platformio.ini`: `env:wc2` ตั้ง `HAS_MQ=1` (อ่าน MQ-137 และส่ง `odor`), `env:wc1` ตั้ง `HAS_MQ=0` (ไม่อ่าน MQ-137 และไม่ส่ง `odor` gateway รู้เองว่า node นี้ไม่มีค่ากลิ่น) |

## ขั้นที่ 5: ทดสอบ ESP-NOW ด้วยบอร์ดรับทดสอบ (พ. 18)

ยังไม่ต้องรอ gateway ใช้บอร์ดตัวที่ 2 ของคุณเป็นตัวรับชั่วคราว

1. เปิด hotspot ชื่อ `OnBed-Hotspot`
2. ใน hwtest ใส่โค้ดนี้แล้วแฟลชลง**บอร์ดตัวที่ 2**:
   ```cpp
   #include <Arduino.h>
   #include <WiFi.h>
   #include <esp_now.h>
   const char *SSID = "OnBed-Hotspot";   // ชื่อ hotspot เดียวกับใน config.h
   const char *PASS = "your-password";
   void onRecv(const uint8_t *mac, const uint8_t *data, int len) {
     Serial.printf("from %02X:%02X:%02X:%02X:%02X:%02X  %.*s\n",
                   mac[0], mac[1], mac[2], mac[3], mac[4], mac[5], len, (const char *)data);
   }
   void setup() {
     Serial.begin(115200);
     WiFi.mode(WIFI_STA);
     WiFi.setSleep(false);
     WiFi.begin(SSID, PASS);
     while (WiFi.status() != WL_CONNECTED) delay(300);
     Serial.printf("Test receiver MAC: %s  channel: %d\n", WiFi.macAddress().c_str(), WiFi.channel());
     esp_now_init();
     esp_now_register_recv_cb(onRecv);
   }
   void loop() {}
   ```
3. ดู Serial ของบอร์ดตัวที่ 2 จด `Test receiver MAC` แล้วใส่ใน `GATEWAY_MAC` ของ node (`config.h`) แปลง `24:6F:28:AA:BB:CC` เป็น `{0x24, 0x6F, 0x28, 0xAA, 0xBB, 0xCC}`
4. แฟลช node (`env:wc2`) ลง**บอร์ดตัวแรก**
5. **ผลที่ต้องเห็น:**
   - Serial ของ node: `ESP-NOW ready on channel 6` แล้วทุก 10 วินาที `{"node_id":"WC-2","seq":0,"odor":1.23,"people":0}  OK`
   - Serial ของตัวรับ: `from 24:..  {"node_id":"WC-2",...}`
   - เอามือผ่านหน้า KY-032 หลายครั้ง (เว้นแต่ละครั้งเกิน 1 วินาที) ค่า `people` รอบถัดไปต้องเท่าจำนวนครั้ง
6. **ทดสอบ retry:** ถอดสายตัวรับ node ต้องขึ้น `send failed (attempt 1/4)` ... `FAILED` ครบ 3 รอบแล้วขึ้น `rescanning channel` เสียบตัวรับกลับ ต้องกลับมา `OK` เอง
7. ถ้าไม่ขึ้น `OK` ดูตารางแก้ปัญหาในข้อ 14

## ขั้นที่ 6: เตรียมบอร์ดตัวที่ 2 เป็น WC-1 (พฤ. 19)

1. เปลี่ยน `GATEWAY_MAC` กลับเป็นค่าตัวอย่างไว้ก่อน (วันศุกร์จะได้ MAC จริงจากสุรสิทธิ์)
2. ต่อ KY-032 ตัวที่ 2 เข้าบอร์ดตัวที่ 2 แบบเดียวกับขั้นที่ 3 (**ไม่ต้องต่อ MQ-137** และไม่ต้องใช้ตัวต้านทาน)
3. เลือก env **`env:wc1`** แล้วแฟลชลงบอร์ดตัวที่ 2 (ชื่อ node และ `HAS_MQ=0` มาจาก `platformio.ini` ไม่ต้องแก้โค้ด) Serial ต้องขึ้น `=== Sensor node WC-1 (MQ-137: no) ===` และข้อความที่ส่งไม่มี `odor` เช่น `{"node_id":"WC-1","seq":0,"people":0}`
4. ติดเทปเขียนชื่อ **WC-1** / **WC-2** บนบอร์ด กันสลับ
5. เก็บสายบน breadboard ให้แน่น ไม่หลุดง่ายเวลาขนย้าย
6. ทดสอบบอร์ด 2 ด้วยวิธีเดียวกับขั้นที่ 5 (ใช้บอร์ด 1 เป็นตัวรับทดสอบชั่วคราว) ต้องขึ้น `{"node_id":"WC-2",...}  OK` แล้วแฟลชบอร์ด 1 กลับเป็น `env:wc1`
7. commit:
   ```bash
   git add firmware/sensor-node
   git commit -m "node: tested WC-1 and WC-2 with test receiver"
   git push
   ```

## ขั้นที่ 7: วันรวมระบบ (ศ. 20)

1. รับ MAC ของ gateway จริงจากสุรสิทธิ์ (gateway พิมพ์ `Gateway MAC: ...` ตอนเปิด)
2. ใส่ใน `GATEWAY_MAC` แล้วแฟลชทั้ง `env:wc1` (บอร์ด 1) และ `env:wc2` (บอร์ด 2)
3. **ต้องเปิด gateway ให้ต่อ hotspot ได้ก่อน** node ถึงจะหา channel ถูก
4. ดู Serial ของ gateway ต้องขึ้นทั้ง `[ESP-NOW] WC-1 ...` และ `[ESP-NOW] WC-2 ...`
5. commit (MAC ไม่ใช่ความลับ commit ได้):
   ```bash
   git add firmware/sensor-node/include/config.h
   git commit -m "node: set real gateway MAC"
   git push
   ```

## ขั้นที่ 8: Calibrate ค่า R0 (ส. 21)

ทำหลัง MQ-137 burn-in ครบ 24 ชั่วโมงแล้ว

1. วางเซ็นเซอร์ในที่อากาศถ่ายเท ไม่มีกลิ่น (ริมหน้าต่างที่เปิดอยู่ หรือนอกอาคาร)
2. เลือก env **`env:calibrate`** แล้วแฟลชลงบอร์ดตัวแรก (WC-2 ที่มี MQ-137) ดู Serial: `V=1.234  Rs=3.0510  beam=0` ทุกวินาที
3. เสียบไฟทิ้งไว้ 30 นาทีให้ค่านิ่งก่อน (heater ต้องอุ่นเครื่อง ระหว่างนี้ยังไม่ต้องจดอะไร) จากนั้นจดค่า Rs **5 ค่า** ห่างกันค่าละ 30 วินาที แล้วหาค่าเฉลี่ย เช่น 3.02, 3.05, 3.07, 3.04, 3.06 → เฉลี่ย = 3.05
   - ใช้ 5 ค่าเพราะ R0 เป็นค่าอ้างอิงตั้งต้น ความคลาดเคลื่อนเล็กน้อยถูกหักล้างไปตอนคำนวณ `odor = R0/Rs` อยู่แล้ว
4. ใส่ค่าใน `platformio.ini` ที่ `env:wc2` แก้แค่ตัวเลขหลัง `MQ_R0_VALUE=` (ไม่ต้องแก้ `env:wc1` เพราะไม่มี MQ-137):
   ```ini
   [env:wc2]
   build_flags = -DNODE_ID=\"WC-2\" -DHAS_MQ=1 -DMQ_R0_VALUE=3.05f
   ```
5. แฟลช `env:wc2` กลับลงบอร์ดตัวแรก ในอากาศสะอาดค่า `odor` ต้องประมาณ 0.9–1.1
6. จดผลลงไฟล์ใหม่ `docs/node-calibration.md` (ต้องใช้ตอนเขียนรายงานข้อ 3.2):
   ```markdown
   # Calibrate MQ-137
   - วันที่: 2026-11-21, สถานที่: ริมหน้าต่างห้อง ..., อุ่นเครื่อง 30 นาที, จดทุก 30 วินาทีเป็นเวลา 5 นาที
   | node | ค่า Rs ที่จด 10 ค่า | ค่าเฉลี่ย (R0) |
   | --- | --- | --- |
   | WC-2 | 3.02, 3.05, ... | 3.05 |
   ```
7. commit:
   ```bash
   git add firmware/sensor-node/platformio.ini docs/node-calibration.md
   git commit -m "node: calibrate MQ-137 R0 for WC-2"
   git push
   ```

## ขั้นที่ 9: ติดตั้งในห้องน้ำจริง (ส. 21 บ่าย – อา. 22 เช้า)

ติดตั้ง node ทั้ง 2 ตัวในกล่องที่ประกอบไว้เช้าวันเสาร์ (ไฟล์ 01 ขั้นที่ 6)


- **WC-1 (ทางเข้า):** ติด KY-032 ที่ผนังข้างทางเดินเข้า สูงระดับเอว (ประมาณ 90–100 ซม.) หันหน้าเซ็นเซอร์ตั้งฉากกับทางเดิน ระดับเอวจะนับคนได้ครั้งละ 1 ไม่นับขาสองข้าง
- **WC-2 (โซนโถ):** วางกล่อง node (ที่มี MQ-137) ใกล้โถสุขภัณฑ์ เพราะกลิ่นแรงที่สุดตรงนี้ ติด KY-032 ที่ข้างทางเข้าโซนโถ (ขอบประตูห้องย่อย) แบบเดียวกัน
- **ระยะสำคัญมาก:** KY-032 ตรวจจับได้แค่ประมาณ 30 ซม. (ตามที่ปรับในขั้นที่ 3) คนต้องเดินผ่านใกล้เซ็นเซอร์ จึงต้องติดที่**จุดแคบที่สุด** ที่ทุกคนต้องเดินผ่าน เช่น ขอบประตู หรือช่องระหว่างผนังกับอ่างล้างมือ
  - ทดสอบก่อนติดถาวร: ถือเซ็นเซอร์ไว้ที่จุดนั้น ให้เพื่อนเดินผ่านแบบปกติ 5 ครั้ง (ทั้งชิดเซ็นเซอร์และเดินกลางทาง) LED ต้องติดทุกครั้ง ถ้าเดินกลางทางแล้วไม่ติด ให้หมุนเพิ่มระยะ หรือย้ายไปจุดที่แคบกว่า
  - ห้ามหันเซ็นเซอร์ไปทางผนังฝั่งตรงข้ามที่อยู่ใกล้กว่าระยะที่ตั้ง (LED จะติดค้าง นับไม่ได้) และหลีกเลี่ยงจุดที่แดดส่องตรง เพราะแสงแดดมีอินฟราเรดทำให้อ่านผิด
- ติดกล่องสูงจากพื้นอย่างน้อย 1 เมตร ห่างอ่างและโถ (กฎความปลอดภัยเรื่องแยกน้ำกับวงจร) ใช้เทปกาวสองหน้าแบบแรงหรือเคเบิลไทร์
- ไฟเลี้ยง: สาย USB ยาว + หัวชาร์จมือถือ 5V 1A ขึ้นไป
- หลังติดเสร็จ เปิด dashboard บนมือถือ เดินผ่าน KY-032 ของแต่ละโซน 5 ครั้ง ต้องเห็นจำนวนคนเพิ่มทั้ง 2 โซน

2. **การนับคนด้วย interrupt (ข้อ E2) 3–4 ประโยค:** อธิบายว่า ISR ทำงานเมื่อขา OUT ของ KY-032 เปลี่ยนเป็น LOW (มีคนผ่าน), ทำแค่เพิ่มตัวนับ, มี debounce 500 ms กันนับซ้ำ, และ loop หลักดึงค่าไปส่งทุก 10 วินาที (deferred processing) ไม่ใช้ busy polling
3. **การวัดกลิ่น 3–4 ประโยค + ตาราง:** voltage divider ลดแรงดัน 5 V → 3.3 V, คำนวณ odor = R0/Rs, วิธี calibrate และค่า R0 ที่ได้ (copy ตารางจาก `docs/node-calibration.md`)
4. **การส่งข้อมูลที่เชื่อถือได้ (ข้อ E4 ฝั่ง node) 3–4 ประโยค:** ESP-NOW มี ACK, ถ้าไม่ได้ ACK ส่งซ้ำรวมไม่เกิน 4 ครั้ง, ถ้าล้มเหลว 3 รอบติดกันจะ scan หา channel ใหม่, จำนวนคนที่ส่งไม่สำเร็จจะเก็บไว้ส่งรอบหน้า
5. **ผลทดสอบส่วน node:** ตารางสรุป 4 แถวจากผล T1, T4, T8, T10 ใน `docs/test-plan.md` และปัญหาที่เจอจาก `docs/node-tests.md`

ใส่รูป 1 รูป: รูปถ่าย node จริงในกล่องที่ติดตั้งแล้ว ใต้รูปเขียน "รูปที่ X sensor node WC-1 ที่ติดตั้งในห้องน้ำ"

## ข้อ 16: คำถามที่อาจารย์น่าจะถาม (เตรียมตอบให้ได้)

1. **ISR คืออะไร ทำไมห้าม print ใน ISR?** ISR ขัดจังหวะโปรแกรมหลักทันที ต้องจบเร็วที่สุด `Serial.print` ช้าและอาจค้าง จึงทำแค่เพิ่มตัวนับ ส่วนการส่งข้อมูลทำทีหลังใน loop
2. **ทำไมตัวแปรต้องเป็น `volatile`?** บอก compiler ว่าค่าอาจเปลี่ยนจาก ISR ได้ตลอด ห้ามเก็บค่าเก่าไว้ใน register
3. **Debounce ทำไม?** คนเดินผ่านหนึ่งครั้ง สัญญาณ KY-032 อาจเปลี่ยนหลายครั้ง (แขน ลำตัว กระเป๋าผ่านทีละส่วน) จึงไม่นับซ้ำภายใน 500 ms
4. **ทำไมต้องรู้ channel ของ hotspot?** ESP-NOW ส่งได้เฉพาะคลื่น channel เดียวกัน gateway ต่อ hotspot จึงถูกบังคับให้อยู่ channel ของ hotspot node จึงต้อง scan หา channel นั้น
5. **ACK ของ ESP-NOW มาจากไหน?** ESP-NOW แบบ unicast มีการตอบรับระดับ MAC ในตัว callback `onDataSent` บอกว่า gateway ได้รับหรือไม่
6. **ทำไม odor เป็น R0/Rs?** ความต้านทานของ MQ-137 ลดลงเมื่อมีแอมโมเนีย การกลับเศษส่วนทำให้ค่าเพิ่มขึ้นเมื่อเหม็น เข้าใจง่ายกว่า และไม่ต้องรู้ค่า RL บนโมดูลเพราะตัดกันตอนหาร
7. **รองรับ node มากกว่า 2 ตัวไหม?** ได้ แค่แฟลชด้วย `NODE_ID` ใหม่ gateway ลงทะเบียน node ใหม่อัตโนมัติ (สูงสุด 4)
8. **ทำไมใช้ KY-032 แทน IR break-beam?** เป็นเซ็นเซอร์ที่ยืมได้จากวิชา ให้สัญญาณ HIGH/LOW แบบเดียวกัน (LOW เมื่อมีคนผ่าน) โค้ด ISR เหมือนเดิม ข้อดีคือติดฝั่งเดียวไม่ต้องเล็งตัวส่งกับตัวรับให้ตรงกัน ข้อจำกัดคือระยะสั้น (~30 ซม.) จึงต้องติดที่จุดแคบ และแสงแดดรบกวนได้
9. **ทำไม MQ-137 มีแค่ WC-2?** กลิ่นแรงที่สุดอยู่ที่โซนโถ วัดจุดเดียวก็พอให้ AI ทำนายได้ ส่วน WC-1 ทำหน้าที่นับคนเข้า เซ็นเซอร์รวมยังครบ 5 ชนิด และยังเป็น node จริง 2 ตัว firmware ใช้ตัวเดียวกัน ปิดการอ่าน MQ-137 ด้วย `HAS_MQ=0`

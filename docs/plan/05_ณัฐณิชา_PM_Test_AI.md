## สิ่งที่ต้องส่งมอบ

- **ข้อมูลจริงต่อเนื่อง** จากห้องน้ำจริง (อย่างน้อย 24 ชม.) ใช้ได้คะแนน Field Test และใช้วัดความแม่นของ AI
- **AI แบบ closed loop** (ข้อ M4): ใช้ **Chronos-2** (โมเดลพยากรณ์ time series สำเร็จรูปของ Amazon ไม่ต้องเทรนเอง โจทย์อนุญาต) ทำนายค่ากลิ่นในอีก 30 นาที แล้วสั่งระดับพัดลมกลับไปที่ gateway

- **Metrics อย่างน้อย 3 ค่า** วัดจากข้อมูลจริง วัดซ้ำ และรายงาน mean/min/max (Metrics 4/4)
- **วิดีโอ checkpoint** (20 พ.ย.) และ**วิดีโอ final 3–5 นาที**
- **รายงานฉบับสุดท้าย:** สร้างไฟล์ Google Doc, เขียนข้อ 1, 3.5, 4, 5 และภาคผนวก ข, รวมทุกส่วนและ export เป็น PDF (ดูไฟล์ 00 ข้อ 8 และขั้นที่ 11)

ไฟล์ของคุณใน starter code: `ai/` ทั้งโฟลเดอร์ (ยกเว้น `notifier.py` ของวัตตะนะ) และ `docs/test-plan.md` (สร้างตามข้อ 5)

## ขั้นที่ 1: ลองทั้งกระบวนการ AI ด้วยข้อมูลจำลอง (จ. 16)

ขั้นนี้สำคัญ: เป็นการเช็กว่า **Chronos-2 ลงและรันบนคอมของคุณได้จริง** ต้องทำให้ผ่านตั้งแต่วันแรก

1. copy `starter-code/ai/` ไปไว้ที่ `onbedsystem/ai/` และ `starter-code/tools/` ไปไว้ที่ `onbedsystem/tools/`
2. ทำ venv และติดตั้ง library ตาม 00 ข้อ 3.2
   - `pip install -r requirements.txt` รอบนี้จะนาน (10–20 นาที) เพราะต้องโหลด PyTorch ซึ่งไฟล์ใหญ่ ใช้ Wi-Fi ที่เร็วและไม่จำกัดปริมาณ
   - ต้องใช้ Python **3.10 ขึ้นไป** (เช็กด้วย `python --version`)
3. copy `ai/config_secrets.example.py` เป็น `ai/config_secrets.py` (ตอนนี้ยังไม่ต้องใส่ค่าจริง)
4. สร้างข้อมูลจำลอง 1 วัน แล้ววัดผล:
   ```bash
   cd tools
   python fake_gateway.py --csv ../ai/data/raw.csv --days 1
   cd ../ai
   python evaluate.py
   ```
   ครั้งแรก `evaluate.py` จะดาวน์โหลดโมเดล Chronos-2 จาก Hugging Face (ประมาณ 500 MB) รอจนเสร็จ ครั้งต่อไปไม่ต้องโหลดอีก
5. **ผลที่ต้องเห็น** (ตัวเลข MAE จะต่างจากนี้):
   ```
   ข้อมูลรายนาที: 1441 นาที (24.0 ชั่วโมง)
   จุดทดสอบ: 136 จุด
   กำลังโหลดโมเดล amazon/chronos-2 (ครั้งแรกจะดาวน์โหลด ~500 MB) ...
   ทำนาย 136 จุด ใช้เวลา 15.0 วินาที (110 ms ต่อจุด)

   MAE (ค่าคลาดเคลื่อนเฉลี่ย ยิ่งน้อยยิ่งดี):
     chronos-2            0.1xxx
     baseline_no_change   0.1502
   เกณฑ์: soon >= 1.803, now >= 2.485

   บันทึก models/config.json และ models/prediction.png แล้ว
   ```
   และไฟล์ `models/prediction.png` (กราฟค่าจริงเทียบค่าทำนาย)
   - ตอนนี้ยัง**ไม่ต้องสนใจว่า MAE ชนะ baseline ไหม** เพราะเป็นข้อมูลจำลอง สิ่งที่ต้องการคือรันจบโดยไม่มี error
6. **ถ้ารันไม่ผ่าน:**
   | อาการ | แก้ |
   | --- | --- |
   | `pip install` ขึ้น error เรื่อง torch | เช็ก `python --version` ต้องเป็น 3.10–3.12 แบบ 64-bit ถ้าไม่ใช่ ลง Python ใหม่แล้วสร้าง venv ใหม่ |
   | ค้างหรือ error ตอนดาวน์โหลดโมเดล | เช็กเน็ต แล้วรันซ้ำ (โหลดต่อจากเดิมได้) |
   | `No module named 'chronos'` | ลืม activate venv |
   | ลองทุกอย่างแล้วยังไม่ได้ | แจ้งในกลุ่มวันนี้เลย จะได้มีเวลาแก้ |
7. ลองรัน `python metrics.py` จะได้ไฟล์ `../docs/metrics/results.md`
8. **ลบไฟล์ที่ได้จากข้อมูลจำลองทิ้งก่อนเก็บข้อมูลจริง** (ทั้ง 4 ไฟล์) รันในโฟลเดอร์ `ai/`:
   ```bash
   rm data/raw.csv models/config.json models/prediction.png ../docs/metrics/results.md
   ```
   - `raw.csv`, `config.json` ถูก `.gitignore` กันไว้ แต่ต้องลบ ไม่งั้นข้อมูลจริงจะต่อท้ายข้อมูลจำลอง
   - `prediction.png`, `results.md` **ไม่ได้ถูกกันไว้** ถ้าไม่ลบอาจเผลอ commit ผลจากข้อมูลจำลองขึ้น GitHub ทั้งสองไฟล์จะถูกสร้างใหม่จากข้อมูลจริงในขั้นที่ 7 และ 10
9. commit โค้ด:
   ```bash
   git add ai/*.py ai/requirements.txt tools/
   git status            # ต้องไม่มี config_secrets.py
   git commit -m "ai: data collector, Chronos-2 forecaster, evaluation, service"
   git push
   ```
   (`ai/notifier.py` ให้วัตตะนะ commit เอง)

### AI ทำงานยังไง (เปิด `features.py`, `forecaster.py` และ `evaluate.py` อ่านคู่กัน)

1. **Chronos-2 คืออะไร:** โมเดลพยากรณ์ข้อมูลอนุกรมเวลา (time series forecasting) ของ Amazon เป็นโมเดลแบบ transformer ขนาด 120 ล้านพารามิเตอร์ ที่ถูกเทรนมาแล้วจากข้อมูลอนุกรมเวลาจำนวนมากหลายประเภท จึงทำนายข้อมูลชุดใหม่ที่ไม่เคยเห็นได้เลยโดยไม่ต้องเทรนเพิ่ม (เรียกว่า zero-shot) เราแค่ป้อนประวัติย้อนหลัง มันจะคืนค่าที่คาดว่าจะเกิดข้างหน้า
2. **รวมข้อมูลเป็นรายนาที** (`to_minutes` ใน `features.py`): ค่ากลิ่น = ค่าสูงสุดของทุก node ที่มี MQ-137 (ตอนนี้มีแค่ WC-2) เฉลี่ยในนาทีนั้น, จำนวนคน = ผลรวมทุก node, ค่า −1 (เซ็นเซอร์หลุด) ไม่นับ, นาทีที่ไม่มีข้อมูลเป็นค่าว่าง ไม่ใช่ 0
3. **สิ่งที่ป้อนให้โมเดล** (`forecaster.py`): ข้อมูลรายนาทีย้อนหลังสูงสุด 6 ชั่วโมง (ต้องมีอย่างน้อย 60 นาที)
   | ข้อมูล | บทบาท |
   | --- | --- |
   | `odor` | ค่าที่ต้องการทำนาย (target) |
   | `people` | จำนวนคนต่อนาที — ข้อมูลประกอบ (covariate) |
   | `temp`, `hum` | อุณหภูมิ ความชื้น — ข้อมูลประกอบ (covariate) |
4. **สิ่งที่ได้กลับมา:** ค่ากลิ่นที่คาดว่าจะเป็นในแต่ละนาทีของ 30 นาทีข้างหน้า เราใช้ค่ากลาง (median) ของนาทีที่ 30
5. **วัดผล** (`evaluate.py`): เลือกจุดเวลาทุก 10 นาทีในข้อมูลจริง ให้โมเดลทำนายจากประวัติก่อนจุดนั้น (โมเดลไม่เห็นข้อมูลหลังจุดนั้น) แล้วเทียบกับค่ากลิ่นจริงในอีก 30 นาที คิดเป็น MAE (ค่าคลาดเคลื่อนเฉลี่ย) และเทียบกับ **baseline** = เดาว่าอีก 30 นาทีค่ากลิ่นเท่าตอนนี้ โมเดลต้องดีกว่า baseline ถึงจะพูดได้ว่า AI มีประโยชน์
6. **เกณฑ์แปลงผล:** ค่าทำนาย ≥ ควอนไทล์ที่ 90 ของค่ากลิ่นจริงที่เก็บมา → `now` (พัดลม 3), ≥ ควอนไทล์ที่ 70 → `soon` (พัดลม 2), ต่ำกว่านั้น → `ok` (พัดลม 1) เกณฑ์นี้ `evaluate.py` คำนวณแล้วเก็บใน `models/config.json`

## ขั้นที่ 4: เก็บข้อมูลจริงต่อเนื่อง (เริ่ม ส. 21)

1. หลังติดตั้งในห้องน้ำจริง (ไอริณนำการติดตั้ง ไฟล์ 01) เปิด `collect.py` บน**คอมที่เปิดทิ้งไว้ได้ทั้งวันทั้งคืน** และต่อเน็ตตลอด (ไม่ต้องอยู่ใกล้ห้องน้ำ เพราะรับข้อมูลผ่าน NETPIE)

   - Mac: System Settings → Energy → ป้องกันไม่ให้ sleep อัตโนมัติ หรือรัน `caffeinate -i python collect.py`
2. **ถ้าคอมดับหรือรีสตาร์ท:** เปิด `python collect.py` ใหม่ ไฟล์ CSV จะต่อท้ายของเดิม ข้อมูลช่วงที่หายยังมีใน NETPIE feed

3. **วิธีวัดผล (2–3 ประโยค):** ทดสอบกับข้อมูลจริงวันไหนถึงวันไหน กี่ชั่วโมง กี่จุดทดสอบ (ดูใน `eval_log.txt`) ให้โมเดลทำนายจากประวัติก่อนจุดทดสอบ แล้วเทียบกับค่ากลิ่นจริงในอีก 30 นาที
4. **ผล:** ตาราง MAE 2 แถว (Chronos-2, baseline) จาก `eval_log.txt` รอบล่าสุด + รูป `prediction.png` ใต้รูปเขียน "รูปที่ X ค่ากลิ่นจริงเทียบค่าที่ทำนาย"
5. **การแปลงเป็นคำสั่ง (1–2 ประโยค):** เกณฑ์ quantile 70/90 ของค่ากลิ่นจริง → พัดลม 1/2/3 และสถานะ ok/soon/now, ถ้า AI หลุด gateway ใช้ fallback

## คำถามที่อาจารย์น่าจะถาม

1. **AI ต่างจาก threshold ยังไง?** threshold ดูแค่ค่าตอนนี้ แต่โมเดลใช้ประวัติค่ากลิ่น จำนวนคน อุณหภูมิ ความชื้นย้อนหลังสูงสุด 6 ชั่วโมง ทำนายว่าอีก 30 นาทีจะเป็นยังไง พัดลมจึงเร่ง*ก่อน*กลิ่นแรง
2. **ทำไมใช้โมเดลสำเร็จรูป ไม่เทรนเอง?** โจทย์อนุญาต และ Chronos-2 ถูกเทรนจากข้อมูลอนุกรมเวลาจำนวนมากมาแล้ว ใช้ได้ทันที (zero-shot) ถ้าเทรนเองต้องเก็บข้อมูลหลายสัปดาห์ถึงจะได้โมเดลที่เชื่อถือได้ เราจึงใช้เวลาไปกับการวัดผลบนข้อมูลจริงของเราแทน
3. **รู้ได้ยังไงว่าโมเดลใช้ได้กับห้องน้ำเรา?** วัดกับข้อมูลจริงที่เก็บเอง: ทุก 10 นาทีให้โมเดลทำนายจากประวัติก่อนหน้า แล้วเทียบกับค่ากลิ่นจริงในอีก 30 นาที ได้ MAE เท่าไหร่ เทียบกับ baseline (เดาว่าไม่เปลี่ยน) เท่าไหร่ (ตอบตัวเลขจาก `eval_log.txt`)
4. **โมเดลรันที่ไหน?** บนคอม (CPU ธรรมดา) ไม่ได้เรียก cloud API ข้อมูลไม่ออกนอกเครื่อง
5. **วัด packet delivery ยังไง?** ใช้ `seq` ของ node เทียบกับจำนวนที่ gateway นับว่าได้รับ
6. **ทดสอบกรณีผิดปกติอะไรบ้าง?** เน็ตหลุด, ไฟดับ (node/gateway), เซ็นเซอร์หลุด, AI หลุด, ปุ่มฉุกเฉิน (T7–T12)

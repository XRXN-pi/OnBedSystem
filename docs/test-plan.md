## 1. ขอบเขตและเงื่อนไขก่อนทดสอบ

ก่อนเริ่มรัน test ทุกข้อ ต้องมีครบตามนี้:

- [ ] sensor node WC-1 และ WC-2 เปิดอยู่ และ Serial ขึ้น `OK` ทุก 10 วินาที
- [ ] gateway ต่อ Wi-Fi hotspot และ NETPIE ได้ (Serial ขึ้น `[MQTT] connected`)
- [ ] dashboard เปิดอยู่และค่าอัปเดต (`wc1_online`, `wc2_online` = 1)
- [ ] `service.py` รันมาแล้ว **อย่างน้อย 60 นาที** (ไม่งั้น AI ยังทำนายไม่ได้)
- [ ] Discord webhook ทำงาน (ลองส่งข้อความทดสอบ 1 ครั้ง)
- [ ] มือถืออัดวิดีโอพร้อม (ทุกข้ออัด 10–20 วินาที เก็บใน Google Drive `test-clips/`)

**กติกาการบันทึกผล**

1. **จำนวนรอบไม่เท่ากันทุกข้อ** ทำตามที่ระบุในหัวตารางของแต่ละข้อ — ข้อที่ผลเป็น *ตัวเลข* ซึ่งต้องรายงานค่าเฉลี่ยและค่าต่ำสุด–สูงสุดทำ 3 รอบ (T1, T2) ข้อที่พิสูจน์ว่าระบบ *กลับมาเองได้* ทำ 2 รอบ (T8, T9) ที่เหลือเป็นข้อ ผ่าน/ไม่ผ่าน ทำ 1 รอบพอ ถ้ารอบแรกไม่ผ่านค่อยแก้แล้วทำใหม่
2. เขียนผลจริงเป็น **ตัวเลขหรือสิ่งที่เห็น** เช่น "รอบ 1: 19/20" ไม่ใช่แค่ "ผ่าน"
3. ข้อที่ไม่ผ่าน ต้องเขียนในคอลัมน์ "ผลจริง" ว่า **เกิดอะไร → แก้ยังไง → ผลรอบใหม่** (ใช้เขียนรายงานข้อ 5)
4. เกณฑ์ผ่าน: ผ่านครบทุกรอบที่ทำ = ผ่าน, ข้อ 3 รอบที่ผ่าน 2/3 = ผ่านแบบมีเงื่อนไข (ต้องเขียนอธิบาย), ต่ำกว่านั้น = ไม่ผ่าน
5. ทำเสร็จแต่ละข้อ ให้ commit: `git add docs/test-plan.md` แล้ว `git commit -m "test: result Txx"` แล้ว `git push`
